# Формат ввода-вывода — Р3, базовый уровень

Программа запускается с флагом способа выбора k ближайших и двумя путями —
к входному и выходному файлу:

    ./solution --method sort   вход.txt выход.txt
    ./solution --method heap   вход.txt выход.txt
    ./solution --method select вход.txt выход.txt

`sort` — полная сортировка всех кандидатов, `heap` — куча размера k,
`select` — быстрый выбор. **Вывод всех трёх способов обязан совпадать**:
`check.py` прогоняет каждый тест трижды, по разу на способ.

## Вход

Текстовый файл. Строки разделяются символом `\n`; завершающий `\r`, пробелы и
табуляции по краям строки отбрасываются. Строка, в которой после этого ничего
не осталось, — пустая и **игнорируется везде**, но номера строк считаются по
файлу с единицы, включая пустые.

Структура (пустые строки между частями допустимы):

    K <k>
    TRAIN
    <метка> || <текст письма>
    ...
    QUERY
    <текст запроса>
    ...

- `K <k>` — первая непустая строка: буква `K`, пробельные символы, целое
  `k` из одних цифр, `1 ≤ k ≤ 10^9`.
- `TRAIN` — вторая непустая строка, ровно это слово.
- Далее строки обучающей выборки до строки, равной `QUERY`. Строка делится
  по **первому** вхождению `||`: слева метка, справа текст. Метка после
  обрезки пробелов непуста и не содержит пробелов и табуляций; это любой
  токен (`ham`, `spam`, `phish`, …). Текст может быть пустым.
- После `QUERY` каждая непустая строка — один запрос, целиком текст (слова
  `TRAIN`, `QUERY`, `||` здесь ничего не значат). Если строки `QUERY` нет,
  запросов нет.

## Слова

Текст превращается в **множество** слов: повторы не важны, порядок не важен.
Разбор побайтовый, слева направо. Буквами слова считаются:

| байты | символы | приводится к |
|---|---|---|
| `30`–`39` | `0`–`9` | — |
| `61`–`7A` | `a`–`z` | — |
| `41`–`5A` | `A`–`Z` | +`20`: `a`–`z` |
| `D0 B0`–`D0 BF`, `D1 80`–`D1 8F` | `а`–`я` | — |
| `D0 90`–`D0 9F` | `А`–`П` | `D0 B0`–`D0 BF` |
| `D0 A0`–`D0 AF` | `Р`–`Я` | `D1 80`–`D1 8F` |
| `D0 81`, `D1 91` | `Ё`, `ё` | `D1 91` (`ё`) |

Любой другой байт — разделитель, в том числе пробел, пунктуация, `₽`, `—`,
`№`, байты некорректного UTF-8 (одиночный `D0` без подходящего второго байта —
тоже разделитель). Слово — максимальная непрерывная последовательность букв,
приведённая к нижнему регистру. `ё` и `е` — разные буквы.

Пример: `ПрИвЕт, SALE75! 10:00 ёЛКА` → `{привет, sale75, 10, 00, ёлка}`.

## Расстояние и соседи

Расстояние между письмами — число слов, входящих ровно в одно из двух
множеств (мощность симметрической разности, она же манхэттенское расстояние
между 0/1-векторами мешка слов):

    d(A, B) = |A| + |B| − 2·|A ∩ B|

Слова запроса, которых нет ни в одном обучающем письме, просто входят в `|B|`.

Для каждого запроса кандидаты — все корректные обучающие письма. Они
упорядочиваются по паре **(расстояние, номер строки письма)** по возрастанию;
этот порядок полный, поэтому k ближайших определены однозначно. Если
корректных писем меньше `k`, берутся все.

Метка запроса — та, что чаще всего встречается среди выбранных соседей. При
равенстве голосов побеждает метка, которая **раньше** встречается в
упорядоченном списке соседей.

## Ошибки

- `bad_header` — первая непустая строка не `K <k>` с допустимым `k`, или
  вторая непустая не `TRAIN`. Номер строки — где обнаружена проблема; если
  файл закончился раньше, чем встретились обе строки, — число строк файла + 1.
  После этой ошибки **больше ничего не выводится**.
- `bad_train_line` — строка обучающей части без `||` или с некорректной
  меткой. Строка пропускается, обработка продолжается.

## Выход

Сначала строки ошибок `bad_train_line` в порядке строк файла:

    ERROR <номер_строки> <код>

Затем по строке на запрос в порядке запросов (нумерация запросов с единицы):

    Q <номер_запроса> <метка> <строка>:<расстояние> <строка>:<расстояние> ...

соседи — в порядке возрастания пары (расстояние, строка). Если корректных
обучающих писем нет, вместо метки и соседей выводится `-`:

    Q <номер_запроса> -

Сравнение вывода потоковое по токенам: пробелы и переводы строк значения не
имеют.

## Пример

Вход:

    K 3
    TRAIN
    spam || Купите со скидкой сегодня!
    ham || Встреча сегодня в 10:00
    spam || Скидка только сегодня, купите
    ham || Отчёт по встрече завтра
    QUERY
    скидка сегодня
    отчёт: встреча завтра

Выход:

    Q 1 spam 5:2 3:4 4:5
    Q 2 ham 6:3 4:6 3:7

Обратите внимание: `скидкой` и `скидка`, `встрече` и `встреча` — разные
слова. Мешок слов не знает морфологии.

## Режим замера

Для отчёта нужно отдельно измерять время **выбора k ближайших**, отделённое от
чтения файла, построения словаря и подсчёта расстояний. Как включается режим
замера (флаг, переменная окружения, отдельная сборка) — на ваше усмотрение;
`check.py` его не вызывает, а результаты замера не должны попадать в выходной
файл.
