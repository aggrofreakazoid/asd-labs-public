# Лабораторные работы курса «Алгоритмы и структуры данных»

Репозиторий с заданиями, публичными тестами и единым проверочным скриптом.
Один скрипт `check.py` обслуживает все шесть работ.

## Как устроен репозиторий

    README.md              общие правила (этот файл)
    PROTOCOL.md            протокол измерений, обязательный во всех работах
    report-template.md     шаблон отчёта
    check.py               проверочный скрипт
    common/                утилиты, общие для нескольких работ

    r1-session-log/        каждая работа — отдельный каталог:
      task.md                условие
      io-format.md           точный формат ввода-вывода
      lab.json               конфигурация проверки (не редактируется)
      solution.example.json  образец манифеста решения
      tests/public/          публичные тесты NN.in / NN.out
      tests/robustness/      входы для проверки устойчивости
      gen.py                 генератор больших входов для замеров

## Что делаете вы

1. Пишете решение на выбранном языке в каталоге работы.
2. Кладёте рядом `solution.json` — манифест, из которого скрипт узнаёт, как
   собрать и запустить вашу программу. Образец — в `solution.example.json`.
3. Гоняете `check.py`, пока все тесты не станут зелёными.
4. Сдаёте: код, `solution.json`, отчёт по шаблону.

## Манифест решения

`solution.json` в каталоге работы:

    {
      "author": "Иванов Иван",
      "language": "C++17",
      "build": "g++ -O2 -std=c++17 -o solution main.cpp",
      "run": "./solution"
    }

`build` — команда сборки; для интерпретируемого языка оставьте пустой строкой.
`run` — команда запуска. Как программа получает вход и выход, зависит от работы
и описано в её `io-format.md`. Для большинства работ путь к входному и выходному
файлам передаётся аргументами командной строки (`io: args` в lab.json), то есть
скрипт вызывает `<run> вход выход`. Ваша программа не должна ничего спрашивать
у пользователя.

## Запуск проверки

    python3 check.py r1-session-log              публичные тесты + устойчивость
    python3 check.py r1-session-log --public      только публичные тесты
    python3 check.py r1-session-log --robustness   только устойчивость
    python3 check.py r1-session-log --bench        прикидочные замеры роста

Зелёный результат по публичным тестам — необходимое, но не достаточное условие.
При приёмке добавляются скрытые тесты на краевые случаи, не описанные в задании.
Замеры в режиме `--bench` — грубая прикидка формы кривой по времени всего
процесса; в отчёт идут ваши собственные замеры внутри программы по PROTOCOL.md,
а не вывод этой команды.

## Ограничения на реализацию

Готовая библиотечная реализация структуры или алгоритма, который является темой
работы, запрещена. В остальных местах стандартная библиотека разрешена. Работы с
обязательными замерами сдаются на компилируемом языке; внутри одной работы язык
один. Подробности — в задании каждой работы и в шаблоне отчёта.

## Устойчивость к враждебному вводу

Программа не должна падать или зависать ни на каком входе. В каталоге
`tests/robustness` лежат заведомо испорченные файлы: пустой, усечённый, с
чужеродными байтами, чрезмерно большой. Проверка считает вход пройденным, если
программа завершилась аккуратно (в том числе с сообщением об ошибке) и не была
убита сигналом и не превысила лимит времени.
