# Формат тестов и запуска — ДЗ1

Корректность всех трёх реализаций проверяется одним и тем же набором тестов
через `check.py`. Для этого программа выполняет команды из файла над
выбранной реализацией словаря и записывает ответы в выходной файл.

## Запуск

    ./solution --impl hash вход.txt выход.txt
    ./solution --impl bst  вход.txt выход.txt
    ./solution --impl tree вход.txt выход.txt

`hash` — хеш-таблица, `bst` — двоичное дерево поиска без балансировки,
`tree` — сбалансированное дерево вашего варианта. **Вывод трёх реализаций
обязан совпадать**: `check.py` прогоняет каждый тест трижды, по разу на
реализацию.

Это отдельная программа-драйвер поверх общего интерфейса (п. 2 `task.md`):
она создаёт контейнер нужной реализации и вызывает его операции. Бенчмарк
пишется отдельно (п. 4) и в этом формате не нуждается.

Сборка и запуск описываются в `solution.json` (образец —
`solution.example.json`). Язык любой; для Python, например:

    {"author": "Фамилия Имя", "language": "Python 3.12",
     "build": "", "run": "python3 src/main.py"}

## Вход

Файл читается **побайтово**, строки разделяются `\n`. Пробельные символы —
пробел, `\t`, `\r`, `\v`, `\f`; они разделяют токены, лишние допустимы.
Строка без токенов (пустая или из одних пробелов) пропускается и ничего не
выводит. Каждая остальная строка — одна команда:

| Команда | Ответ |
|---|---|
| `INSERT <ключ> <значение>` | `NEW`, если ключа не было; `UPDATED`, если был (значение перезаписано) |
| `FIND <ключ>` | значение или `NOT_FOUND` |
| `ERASE <ключ>` | `ERASED` или `ABSENT` |
| `SIZE` | число ключей |
| `DUMP` | строка `DUMP <n>`, затем n строк `<ключ> <значение>` по возрастанию ключа |

- **Ключ** — от 1 до 256 байт, каждый байт больше `0x20` и не равен `0x7F`
  (то есть без пробелов и управляющих символов; UTF-8 допустим). Ключи
  сравниваются **побайтово**, как беззнаковые числа: `"10" < "9"`,
  `"B" < "a"`, `"a" < "aa"`, кириллица после латиницы.
- **Значение** — целое со знаком в диапазоне 64-битного `int`
  (от −9223372036854775808 до 9223372036854775807): необязательный `-`, затем
  цифры; ведущие нули допустимы (`007` — это 7). Знак `+`, дробная часть,
  экспонента и выход за диапазон — ошибка.
- Имена команд — ровно как в таблице, с учётом регистра.

## Ошибки

Строка, не подходящая ни под одну команду (неизвестная команда, не то число
аргументов, некорректный ключ или значение), даёт ответ `BAD`, и содержимое
словаря не меняется. Обработка продолжается со следующей строки.

Программа не должна падать или зависать ни на каком входе, включая пустой,
двоичный, с огромными строками и с тысячами ключей одного хеша.

## Выход

По одной строке ответа на каждую непустую команду; у `DUMP` — n + 1 строк.
Сравнение вывода потоковое по токенам: пробелы и переводы строк значения
не имеют.

## Пример

Вход:

    INSERT banana 3
    INSERT apple 5
    INSERT cherry -2
    FIND apple
    FIND grape
    INSERT apple 7
    SIZE
    ERASE banana
    ERASE banana
    DUMP

Выход:

    NEW
    NEW
    NEW
    5
    NOT_FOUND
    UPDATED
    3
    ERASED
    ABSENT
    DUMP 2
    apple 7
    cherry -2

## Проверка

    python3 check.py hw1-dict                # публичные тесты + устойчивость
    python3 check.py hw1-dict --bench        # прикидочный рост времени

Публичные тесты покрывают в том числе: удаление корня и узлов с двумя
сыновьями, вставку отсортированных ключей (BST вырождается в список
глубиной в тысячи узлов), ключи с одинаковым хешем и удаление среди них,
долгий поток вставок и удалений при малом числе живых ключей. Зелёный
результат по публичным тестам необходим, но не достаточен: при приёмке
добавляются скрытые тесты.
